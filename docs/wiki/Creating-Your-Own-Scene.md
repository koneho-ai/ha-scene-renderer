# Creating Your Own Scene

## Format: GLB

Models are **glTF 2.0 binary (.glb)**. Build one however you like — export from Blender (File → Export → glTF 2.0, format **GLB**), generate one in code (the sample apartment is generated by `scripts/generate_sample_model.py` in the repo, pure Python, no dependencies), or convert from another format. Any GLB with named `KHR_lights_punctual` lights works.

## The naming conventions the integration relies on

**Lights.** Lights are glTF `KHR_lights_punctual` lights with a unique `snake_case` `name` (e.g. `living_room_ceiling`). That name is the identifier the integration maps to an HA entity in the setup flow — every named punctual light in the model is an enumerable scene light, shown as one entity picker. Types supported: `point`, `spot`, `directional`. The model's intensity is the "full brightness" look and its color is the default color; the entity's brightness and color scale on top of them (see [[Configuration]]). Intensities are candela (physical units, three.js r155+ default).

In Blender, punctual lights export as `KHR_lights_punctual` when the exporter option is enabled (it is by default for point/spot/sun lights in recent Blender versions) — name the light object in Blender and the name carries into the glTF.

**Cameras.** Cameras are glTF cameras with a unique `snake_case` name set on **both** the camera definition and its node (e.g. `overview`, `living_room`). Three.js names a loaded camera from the definition's name, while model authors see the node name — set both so they agree. Position, look-at target, FOV, and clip planes come from the model, and can be overridden per camera in `cameras.yaml`.

**If the model has no cameras**, you get three built-in virtual cameras computed from the model's bounding box, so they adapt to any size:

| Name | Framing |
| --- | --- |
| `overview` | Isometric dollhouse |
| `topdown` | Straight down, north up |
| `front` | Low front elevation |

**Objects for scripting.** Any named node (mesh, group, camera) can be moved, rotated, scaled, or hidden from `scene.js` via `scene.getObject(name)`. Note that only nodes with real transforms are usefully animatable: a group node (like the sample's `ceiling_fan` or `blinds`) carries a transform, while a mesh whose position is baked into its geometry does not. See [[Scene Scripting]].

## Installing your model

1. Put the `.glb` in `/share/scene-renderer/models/` on the HA host (create the folder if needed).
2. Set the app's `model` option to the file name and restart the app. (The option also accepts a bundled model name or a literal path.)
3. Update the `lights` mapping in the YAML block to the new model's light names (and the `cameras` list if you want to limit which cameras get image entities), then restart Home Assistant — the integration re-reads the light and camera lists from the app at startup.

## Tips

- Keep the model small and low-poly: rendering is software (CPU) on hosts without a GPU, and every render re-renders the whole scene.
- Leave the ceiling off (dollhouse style) if you want an overview camera to see inside — the sample apartment has no ceiling for exactly this reason.
- Model units are metres by convention; `cameras.yaml` positions and targets are in model units.
- If you want motion in clips, add glTF animations to the model (the sample's fan does one full turn per 3 s, matching the default clip duration) — see [[Motion Clips]].
