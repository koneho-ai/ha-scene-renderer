# Panel

The integration adds a **Scene Renderer** entry to the Home Assistant sidebar: a full-page interactive 3D view of the model, rendered in your browser with three.js. No extra setup — it appears once the integration is configured from YAML, and doesn't appear if the YAML block is removed.

## What you see

- **The model** — the same GLB the app renders, loaded from the app through the integration (the browser cannot reach the app directly). Drag to orbit, scroll to zoom, right-drag to pan.
- **Light markers** — one marker at each model light's position, colored by the light's live state: on lights show their current color and brightness, off/unavailable lights are dim gray, unmapped lights are neutral white but dim (they render off, like the script renders them). Markers update live as entities change.
- **Camera markers** — where each camera sits and where it points. Click one to jump the 3D viewer to that camera's viewpoint (adopting its projection — an orthographic camera views orthographic) and see its latest render. The side list shows every camera with its effective resolution.
- **Object markers** (purple) — one on each mapped object (the ceiling fan, the TV screen), so they are findable in the viewer. Click one for its state.
- **Sun marker** — the sun's position from `sun.sun`, hidden while the sun is below the horizon.
- **Side list** — at the top, every subscribed entity (entity id, live state) with a real toggle and, for lights that report a brightness, a brightness slider; below it, every model light (model name, live state) with a debug toggle; then every mapped object (object name, live state) with a real toggle, and every camera. The panel never shows which entity drives which light or object — the mapping lives in the scene script, and the panel doesn't try to figure it out.
- **Real entity toggles, debug light toggles** — the entity and object toggles call the real Home Assistant service (a light's toggle flips the actual light; a media player's toggle pauses/plays it), so the viewer follows the real house. The Lights section's toggles are debug-only: flipping one sets a local preview override for that model light in the viewer only, so you can try "what if this light were on" without touching the real house. Overridden light rows are marked "(preview)"; **Reset preview** (next to the Lights heading) clears the light overrides and returns the viewer to the real entity states. Overrides are session-local (gone on reload) and never affect the renders. The fan spins in the viewer while its driving entity is on, and the TV screen is visible while its media player is playing, paused or idle.
- **Entities section** — the entities the integration subscribes to (the YAML `entities` list plus the script's subscriptions and the object drivers), each with its live state, a real toggle for toggleable domains, and a brightness slider for lights that report a brightness (releasing the drag calls `light.turn_on` with the chosen brightness — 0 turns it off). No mapping is shown: no "drives" text, no entity-to-light links. A direct light toggle (Lights section) wins over the entity: if a light is toggled directly, it stays on or off no matter what its entity does, until Reset preview clears it. The TV glow is a fallback only when neither is set: with the TV on and its light's entity off, `living_room_tv` still glows (state "tv").
- **Time-of-day sun slider** — a Sun section with a 00:00–24:00 slider moves the viewer's sun to the chosen time (computed from your latitude/longitude, shown with its elevation/azimuth), and a day-of-year slider next to it (1–365, showing the date, e.g. "21 Jun") moves the sun through the seasons — the same NOAA calc, for the chosen date, so a June noon sits high and a December noon stays low. **Live** returns both sliders to the real time and date. Viewer-only: it never affects the renders or the real sun. At night slider positions the viewer shows moonlight too — a dim directional moon (same ephemeris as the renders, computed for the slider's time and season) with its position in the label (`· moon el 34.9°, az 89.1°` when the moon is up), fading in as the slider's sun sets.
- **Weather** — a Weather section with four presets: **sunny** (the normal look), **overcast** (dim sun, flat bright sky, grey backdrop), **rainy** (darker, plus falling rain outside the house), and **snowy** (bright diffuse light, cool backdrop, falling snow). Rain and snow are real particles falling around the house exterior — never inside the rooms. Viewer-only, like the sun slider: the renders are always sunny. The sun and moon follow the YAML `north_offset` too, so the viewer agrees with the renders when the house is rotated (see [[Configuration]]).

The panel re-fetches its data (light mapping, entities, sun, cameras, script entities) when the frontend reconnects after a Home Assistant restart, so a page loaded before the restart picks up the new data without a manual reload.

## How it works

The panel is a custom element registered by the integration (`frontend.async_register_built_in_panel` with `component_name="custom"`). It runs inside the Home Assistant frontend, so it has the live `hass` object — light states come straight from the state machine, no polling.

Data comes from the integration, not the app: the app doesn't know the light mapping (it lives in the scene script), so the panel asks the integration over the websocket API:

- `scene_renderer/panel_entries` — the configured scenes (YAML-only: exactly one).
- `scene_renderer/panel_data` — for one scene: the light mapping from the script (`light_mapping`: model light name → entity id), the subscribed entities (`entities`: the YAML list plus the script's subscriptions and the object drivers — the Entities section), the object mapping (model object name → driving entity id, from the YAML `objects` block), the cameras with their effective config, the image entity id per camera, the effective sun, the moon position (`moon: {elevation, azimuth}`, from the coordinator's lunar ephemeris — `null` when the sun is disabled), the north offset (`north_offset`, degrees — the viewer rotates its sun/moon azimuths by it, see [[Configuration]]), and the script data (`script_entities`, `script_object_drivers`). The Objects section merges the YAML object mapping with the script's `objectDrivers`, YAML winning on conflict.

The model itself comes from the app's `GET /model` endpoint, proxied by the integration at `/api/scene_renderer/<entry_id>/model` — the browser can't reach the app's internal address. The camera previews use the standard image proxy (`/api/image_proxy/<entity_id>`).

Three.js is vendored into the integration (`custom_components/scene_renderer/frontend/` — `three.module.js`, `OrbitControls.js`, `GLTFLoader.js` from the three package the app uses), so the panel works with no build step and no CDN.

## If the panel is empty or shows an error

- **"Not configured"** — no `scene_renderer` block in `configuration.yaml` yet. Add one (see [[Configuration]]) and restart Home Assistant.
- **"Render service unreachable"** — the app is down or its URL changed. Check the app is running (Settings → Apps → HA Scene Renderer) and the `service_url` in the YAML block (or that Supervisor discovery can find the app).
- **The panel entry is missing from the sidebar** — the panel registers when the integration is set up from YAML. Restart Home Assistant and check the sidebar again. A browser hard refresh (Ctrl+Shift+R) clears a stale frontend cache.
- **The model loads but markers are wrong** — markers come from the model the app currently has loaded. If you changed the app's `model` option, restart the app, then restart Home Assistant so the mapping matches the new model.
